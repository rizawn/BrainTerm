### 5.3 Data flow for a create-note click

1. Editor click handler resolves the link with `bt_link_resolve()`, using the same index snapshot as the editor.
2. Status is `BT_LINK_UNRESOLVED`. Editor calls `bt_createnote_plan(vault, source_note, raw_target)`.
3. Planner returns one of: `PLAN_OK` (with a target relative path), `PLAN_NOT_A_NOTE`, `PLAN_OUTSIDE_VAULT`, `PLAN_INVALID_NAME` (with reason), `PLAN_PLACEHOLDER`, `PLAN_EXISTS` (the file already exists, so open it instead).
4. Editor shows the popover for `PLAN_OK` only. Other results show a status-bar message (for example "Not in vault", "Invalid name: contains ':'") and no popover, except `PLAN_EXISTS`, which opens the existing note.
5. User presses Create. UI calls `bt_createnote_commit(plan)`.
6. Commit re-checks existence under the vault write lock, then creates the folder path segment by segment, writes the file with create-only semantics via `vault_atomic_write()` in create mode, and returns the committed path.
7. UI flushes nothing (the source note is not changed), asks the index to upsert the new note, re-resolves links, then opens the new note through the existing open path (the same path used by the link click and history).
8. Navigation history pushes the source note, as a normal link jump does.

### 5.4 Data flow for an ambiguous click

1. Resolver returns `BT_LINK_AMBIGUOUS` with a ranked candidate list.
2. Editor shows the chooser popover anchored to the link.
3. User selects a candidate with the mouse or keyboard, or cancels.
4. Selection opens the candidate through the normal open path, and pushes navigation history.
5. The source file is never written.

### 5.5 Threading

- Planning runs on the GTK main thread. It only reads the index snapshot, which is immutable.
- Commit does file I/O. It runs on a worker through `GTask` so the UI never blocks. The popover shows a busy state until the result returns.
- The index upsert and re-resolve run on the index thread, as they already do for watcher events.
- Results return to the main thread through `g_main_context_invoke` or `GTask` completion.

### 6.1 L3-1: Create-note popover

#### 6.1.1 Trigger

- Click (or `Ctrl+Enter` with the caret inside the link) on an UNRESOLVED link whose planner result is `PLAN_OK`.
- The popover is anchored to the link span. If the span is scrolled out of view, the popover is anchored to the caret line.

#### 6.1.2 Content

- Title: `Create "<display name>"?` where display name is the target without folders and without `.md`.
- Body line 1: the exact vault-relative path that will be created, in monospace. Example: `statistical-statistics-notes/chapter-01-descriptive/03-numerical-description.md`.
- Body line 2 (muted): `Created next to this note` when the target had no folder, or `Folder will be created if missing` when it did.
- Buttons: `Create` (suggested action, default focus) and `Cancel`.
- Keyboard: `Enter` activates Create, `Esc` activates Cancel. Tab cycles between the two buttons.

#### 6.1.3 Path rules (planner)

Apply these rules in order. The first failing rule determines the planner result.

1. Empty target or whitespace-only target: `PLAN_INVALID_NAME`, reason "Empty name".
2. Target contains a PLACEHOLDER pattern `{{...}}`: `PLAN_PLACEHOLDER`. No popover, no message.
3. Target resolves outside the vault by the L1 resolver rules: `PLAN_OUTSIDE_VAULT`, reason "Outside the vault".
4. Target has an extension that is not `.md` or `.markdown`, after stripping a trailing `#anchor` and `|alias`: `PLAN_NOT_A_NOTE`, reason "Not a note (file type .xyz)". Note: a target with no extension is a note name and gets `.md` appended.
5. Target ends with `/` or names a folder that exists: `PLAN_NOT_A_NOTE`, reason "Folder".
6. Any segment is a Windows reserved device name (`CON`, `PRN`, `AUX`, `NUL`, `COM1` to `COM9`, `LPT1` to `LPT9`), with or without extension: `PLAN_INVALID_NAME`, reason "Reserved Windows name".
7. Any segment or the final name contains one of `< > : " | ? *` or a control character: `PLAN_INVALID_NAME`, reason "Contains a character Windows does not allow: X".
8. Any segment ends with a dot or a space: `PLAN_INVALID_NAME`, reason "Name ends with a dot or space".
9. Any segment is `.` or `..`, or the normalized path leaves the vault root: `PLAN_OUTSIDE_VAULT`.
10. Target path (case-folded on Windows, NFC-normalized) matches an existing file in the index snapshot: `PLAN_EXISTS`, carrying the existing path. Editor opens it and shows no popover.
11. Target path matches an existing file on disk but not in the snapshot (stale index): `PLAN_EXISTS` with the disk path. The planner must check disk for this case. Report the stale index in the status bar as "Index refreshed".
12. Otherwise: `PLAN_OK` with the relative path, the parent folder chain that must be created, and the display name.

Path construction:

- Source of relative paths: if the target contains a `/`, it is relative to the source note's folder (matching the L1 Stage 3 rule). If the target has no `/`, the new note is created in the source note's folder.
- Explicitly rooted targets (leading `/`) are rejected: `PLAN_INVALID_NAME`, reason "Absolute paths are not allowed".
- Backslashes in targets are normalized to `/` before the rules above, matching L1.
- Percent-decoding follows L1 (for Markdown-style targets only).
- The `.md` extension is appended only when the target has no extension.

#### 6.1.4 Commit rules

1. Re-run the planner's disk check under the vault write lock. If the file now exists: do not write. Return `COMMIT_EXISTS`. UI opens the existing file and shows "Note already existed, opened it".
2. Create each missing folder segment one at a time. Each segment goes through the same path guard as files. If a folder segment already exists as a file (not a folder), return `COMMIT_BLOCKED` with reason "A file named X is in the way".
3. Write the note to a temp file in the same folder, using a name that cannot collide with a note (for example `.bt-create-<random>.tmp`). Then rename it to the final name with create-only semantics. If the rename target exists at that instant, delete the temp file and return `COMMIT_EXISTS`.
4. Never overwrite. Never use a rename mode that replaces an existing file.
5. On any failure after a folder was created, do not remove the folder unless it is empty and was created by this operation. Report it.
6. The source note is never opened for write during commit.
7. Commit returns the committed relative path and the note id.

#### 6.1.5 Note id and template

- Use the existing id generator found in G-4. Do not write a new generator.
- Frontmatter keys and order come from the existing template function found in G-3. If no template function exists for human notes, create one in `src/createnote.c` that writes exactly these keys in this order:

```
---
id: <generated id>
title: "<display name>"
created: <ISO 8601 local time with offset, same format as existing notes>
updated: <same as created>
source: human
agent: null
tags: []
tags_ai: []
links: []
---

# <display name>

```

- The title line uses the display name. Quote the title in YAML and escape `"` and `\`.
- The body after frontmatter is one H1 line and one blank line. No other content.
- The file is written with LF line endings. If the vault uses CRLF elsewhere, match the vault's existing convention only if the template function already does so. Report which convention was used.
- A UTF-8 BOM is not written.

#### 6.1.6 After commit

1. Index upsert for the new note (on the index thread).
2. Re-resolve all link_resolutions rows whose raw target matches the new note by stem, path, or title. This is the step that turns the old UNRESOLVED link into RESOLVED.
3. Editor refreshes link spans. The original link now shows the resolved style, without the source note being modified on disk. The buffer contents are unchanged.
4. Graph view: if open, rebuild its graph model on the next idle tick. The former ghost node for this target must disappear, and the new note must appear. Do not move other nodes.
5. Open the new note through the normal open path, and push navigation history.
6. Status bar shows `Created <relative path>` for 4 seconds, muted style.

#### 6.1.7 Failure messages

Every failure becomes a status-bar message. None becomes a modal dialog.

| Result | Status-bar message |
|---|---|
| `PLAN_INVALID_NAME` | `Can't create: <reason>` |
| `PLAN_OUTSIDE_VAULT` | `Can't create: outside the vault` |
| `PLAN_NOT_A_NOTE` | `Not a note: <reason>` |
| `COMMIT_BLOCKED` | `Can't create: <reason>` |
| I/O error on write | `Create failed: <OS error text, short>` |
| I/O error on rename | `Create failed: temp file left at <path>` (and the temp is cleaned up when possible) |

#### 6.1.8 Double-click and repeat protection

- While a commit is in progress, the Create button is disabled and shows a spinner or "Creating...".
- A second Create press while busy is ignored.
- After commit, the popover closes. A second click on the same link now resolves to RESOLVED and simply opens the note.

#### 6.1.9 Cancel

- Cancel closes the popover. Nothing is written, nothing is indexed, nothing is recorded in navigation history.
- The caret position does not change.

### 6.2 L3-2: Ambiguity chooser

#### 6.2.1 Trigger

- Click on an AMBIGUOUS link, or `Ctrl+Enter` with the caret inside it.

#### 6.2.2 Content

- A list of candidates from the resolver's ranked list.
- Each row: filename on the first line (bold is allowed only for the selected row), vault-relative folder path on the second line in muted style.
- The first row is preselected. This is the resolver's top-ranked candidate.
- Maximum 10 rows visible, scrolling beyond that. Show a footer `+N more` when there are more than 10 candidates.
- Footer buttons: `Open` (default), `Copy full path link`, `Cancel`.

#### 6.2.3 Keyboard

| Key | Action |
|---|---|
| Up, Down | Move selection, wrapping at ends |
| Home, End | First and last candidate |
| Enter | Open selected candidate |
| Esc | Close without opening |
| Ctrl+C with a row selected | Copy full path link `[[folder/name]]` for that row |

#### 6.2.4 Copy full path link

- Copies a wikilink to the clipboard, using the selected candidate's vault-relative path without `.md`: `[[statistical-statistics-notes/MathStats]]`.
- The link text in the source note is not changed.
- After copy, status bar shows `Copied link for <name>` for 3 seconds.
- The chooser stays open after copy so the user can still open a candidate. Copy alone does not close it.

#### 6.2.5 Open

- Open runs through the normal open path, so navigation history is pushed.
- Opening a candidate that was deleted after the snapshot was built: status bar `That note no longer exists`, and the index is refreshed.

#### 6.2.6 Edge cases

- Zero candidates when the chooser opens (index changed between click and open): close the chooser and show `No matching notes now`. Do not show an empty popover.
- One candidate after re-resolve: open it directly, no chooser.
- Candidate list changes while open (watcher event): keep the list as it was when opened. Show nothing. Refresh only on next open.

## 15. Threat model for create-note

Assets to protect: the vault contents outside the target, the user's other files on disk, the index consistency, and the source note's text.

| Threat | Vector | Control | Test |
|---|---|---|---|
| Path traversal creates a file outside the vault | `../../x` in a link | Planner rule 9, path guard on every segment | CR05, CR04 |
| Symlink or junction redirects the write outside the vault | Pre-existing symlink in a folder segment | Path guard follows real path, rejects if outside | CR37 |
| Overwrite of an existing note | Race between plan and commit | Create-only rename, re-check under lock | CW03, CW06 |
| Overwrite of a file that is not a note | Target name matches a binary file | Planner rule 4 blocks non-note extensions | CR09, CR10 |
| Reserved device name hangs or writes to a device | `CON`, `NUL`, `COM1` | Planner rule 6 | CR16, CR17, CN group |
| Alternate data stream write | `name.md:stream` | Rule 7 blocks `:` | CR19 |
| Name injection in the frontmatter | Display name containing `"`, newline, or YAML syntax | Title escaping, newline rejected | CW12, CT group |
| Template injection | Template values taken from link text | Only the display name is inserted, escaped. No other user text is inserted. | CT group |
| Create triggers an agent | Create writes into agent-watched paths | Agents are not triggered by create. Watcher event is handled as a normal user file. | CX04 |
| Silent creation without consent | Click without popover | Popover is required. Click path only opens the popover. | CX08 |
| Stub writer silently writes | Legacy path still reachable | Routing proof and removal | CX08, grep proof |
| Denial of service by huge names | 10 MB target | Raw target length cap 1024 bytes, already from L1 | CR31 |
| Disk fills during commit | Partial write | Temp file, cleanup on failure, status message | CW05, CW13 |

Rules the implementer must follow:

- Never build a file path with string concatenation of user text without passing it through the planner.
- Never call `system()`, `CreateProcess`, or any shell for file creation.
- Never log the full display name at a level that goes to disk outside the vault log.
- The planner is the only producer of a `BtCreatePlan`. Commit accepts only a plan object, never raw strings.

4. Total parser: for any input bytes, the parser returns an AST (possibly partial) and an error list. It never aborts, never calls `exit`, never dereferences an invalid pointer.
5. Every limit in section B.17 of the mega prompt is enforced and tested. The defaults: inline source 4096 bytes, display source 16384 bytes, AST depth 64, AST nodes 5000, matrix 20x20, draw ops 20000, layout soft cap 50 ms.
6. Deterministic output: the same input always produces the same AST and the same draw list.
7. No allocation in the replay path (M4 uses it; M3 must expose the draw list as a flat array).
8. Fuzz harness runs locally with a fixed seed and in CI with more iterations. Zero crashes required. Sanitizers are not available on MSYS2 UCRT64 (P0 finding); record that and use the Linux CI configuration for ASan and UBSan runs.

### M2 goal

Turn a LaTeX math source string (the content between delimiters, as produced by M1 `bt_math_scan`) into an AST that M3 can lay out. Support Tier 1 commands and the Tier 2 commands listed below. Reject TeX programming with clear errors.

### M2 public API (shape; adapt names to repository style)

```c
typedef struct BtMathArena BtMathArena;
typedef struct BtMathNode BtMathNode;

typedef enum {
  BT_MATH_NODE_ROW, BT_MATH_NODE_ATOM, BT_MATH_NODE_OPNAME, BT_MATH_NODE_SCRIPTS,
  BT_MATH_NODE_FRAC, BT_MATH_NODE_SQRT, BT_MATH_NODE_DELIM, BT_MATH_NODE_ACCENT,

  BT_MATH_NODE_SPACE, BT_MATH_NODE_STYLE, BT_MATH_NODE_ERROR

  gsize offset;      /* byte offset within the source string */
  gsize length;
```

- `BtMathMode` is the M1 enum (inline or display).
- `BtMathParseOpts` carries limits, with defaults from B.17. Tests may lower limits to test behavior.
- Every node holds `src_start` and `src_end` byte offsets within the source.

### M2 tokenizer rules (math mode)

- Whitespace is ignored, except that a control word (`\name`) ends at the first non-letter. `\alpha x` and `\alphax` differ.
- Control symbols: `\` followed by a single non-letter (`\,`, `\;`, `\!`, `\{`, `\}`, `\\`, `\%`, `\$`, `\&`, `\#`, `\_`, `\ `). Each has a defined meaning from B.6.2 and B.6.6.
- `%` starts a comment that runs to end of line (matching TeX). Inside a single-line inline source this means the rest of the source is comment. Record as a warning, not an error.
- `&` and `\\` are row and column separators only inside environments. Outside, they are errors with column.
- Braces `{` `}` are groups. Unbalanced braces are errors with the column of the unmatched brace.
- `^` and `_` are script operators. Double script (`x^a^b`) is an error. Prime `'` after a base is a prime count.
- Unicode input inside math (for example `α` written directly) is accepted as a symbol if the font has it. Record each such character as a symbol atom with its code point.

### M2 command registry

- Table-driven. Each entry: name, required argument count, optional argument count, kind, atom class, and either a code point, a glyph name, or a handler id.
- Registry covers every Tier 1 command in mega prompt B.6, and every Tier 2 command marked for M2 in B.6 (B.6.1 Tier 2 items: `\big` family, `\displaystyle` family, `\substack`, `\overset`, `\underset`, `\stackrel`, `\xrightarrow`, `\xleftarrow`, `\overbrace`, `\underbrace`, `\mathbin` family, `\mathscr`, `\mathfrak`, `\boldsymbol`, `\bm`, `\gather`, `\array`, `\tag`).
- Tier 3 commands (`\cfrac`, `\phantom` family, `\boxed`, `\cancel`, `\hspace`, `\mathnormal`, `\smallmatrix`, `\check` and other accents) may be deferred. If deferred, parsing them returns a clear error with the name, and the test list records each deferred command with the reason.
- Explicit blocklist from B.6.10: `\input \include \write \read \openin \catcode \def \let \csname \expandafter \newenvironment \usepackage \documentclass \begin{tikzpicture}`. Each returns an error naming the command. None is executed.
- Unknown commands return an error and a placeholder `ERROR` node. Parsing continues.

### M2 grammar handling

- Scripts: `atom script*` where script is `^arg`, `_arg`, or primes. Order of sub and sup does not matter. Two superscripts or two subscripts on the same base is an error.
- Groups: `{ expr }`. Empty group `{}` is valid.
- Fractions and similar take exactly two braced or single-token arguments.
- `\left` delimiter ... `\right` delimiter, with optional `\middle`. Mismatch is an error with both columns.
- `\begin{name} ... \end{name}`. Name mismatch is an error with both names and columns. Environments in the acceptance list: `matrix pmatrix bmatrix Bmatrix vmatrix Vmatrix cases aligned align align* split gather gather* array smallmatrix equation equation*`.
- Environment body: rows separated by `\\`, cells by `&`. Ragged rows are allowed for `array` and `aligned`, and are errors for matrix types (rule recorded in the test).
- `\text{...}`: the braced content is kept as a TEXT node. Inside text, math specials are not parsed.
- `\operatorname{name}` and `\operatorname*{name}`: OPNAME node with the name upright.
- `\tag{...}`, `\label{...}`, `\nonumber`, `\notag`: accepted. `\tag` produces a TAG annotation node. `\label` and the no-number commands are ignored with no warning.

### M2 error model

- Every error has: message, byte offset, length, line, column.
- Messages are English, short, and name the offending token. Examples: `Unknown command \foo`, `Expected } to close group opened at column 12`, `\right does not match \left( at column 20`, `Double superscript at column 7`.
- Recovery: after an error, the parser skips to the next safe point (end of group, next `&`, next `\\`, end of input) and continues. The partial AST marks the failed region with an ERROR node carrying the original source slice.
- The parser returns at most 64 errors per formula. Beyond that, it stops and sets `truncated`.

### M2 limits (enforced and tested)

| Limit | Default | Behavior when exceeded |
|---|---|---|
| Source length, inline | 4096 bytes | Error "Formula too long", no parse |
| Source length, display | 16384 bytes | Same |
| Depth | 64 | Error at the deepest point, subtree replaced by ERROR |
| Node count | 5000 | Error, `truncated = TRUE`, parse stops adding nodes |
| Matrix rows or columns | 20 x 20 | Error on the row or column that exceeds |
| Error count | 64 | `truncated = TRUE` |

### M3 font loading

### M3 layout engine

Follow mega prompt sections B.9.1 to B.9.6. Restated here as requirements:

- Units: em, floats. Output is independent of font size and DPI.
- Styles: D, T, S, SS, each with a cramped variant. Start style: D for display, T for inline.
- Script scale: from `ScriptPercentScaleDown` and `ScriptScriptPercentScaleDown`.
- Box model: width, height, depth, italic correction, accent attachment, atom class.
- Atom spacing: full 8 by 8 table from B.9.3, including the star rule (space only in D and T), the unary Bin-to-Ord rule, and explicit spacing commands added to the table spacing.
- Constants: all constants listed in B.9.4. Read them from the MATH table, not from hard-coded numbers.
- Scripts: sup and sub placement with shift constants, cramped handling, gap minimums, italic correction, math kerning if present.
- Fractions: numerator and denominator in the next smaller style, center on the axis, rule thickness from the font, display and text constants by style. Binomial stack without rule, with delimiters sized to the stack.
- Radicals: variant selection, assembly when no variant is tall enough, overbar rule, index placement with kern constants.
- Big operators: display-size variant, limits above and below in D style for `\sum`, `\prod`, `\lim`-like, side limits in T style. `\limits` and `\nolimits` override. `\int` uses side limits by default.
- Delimiters: `\left` and `\right` size from max height and depth above and below the axis, with `DelimitedSubFormulaMinHeight`. `\big` family uses fixed ratios.
- Accents: base height from constants, wide accents choose a fitting variant, attachment from top accent attachment of the base.
- Matrices and cases: columns sized to the widest cell, rows to the tallest ascent and deepest descent, baseline skip about 1.2 em, column gap 1 em, delimiters stretched to the block and centered on the axis.
- Aligned: `rl` column pairs, inter-pair space 2 em.
- Text: upright, normal word spacing, no space rendered after a control word.
- Operator names: upright with thin spaces per TeX rules.
- Output: flat `BtDrawOp` array in em units, plus width, height, depth, error flags, and a warning list.
- Draw op cap: 20000. Exceeding it returns a layout error.
- Soft time cap: 50 ms per formula, measured with a monotonic clock. Exceeding it aborts layout and returns an error for that formula only.
